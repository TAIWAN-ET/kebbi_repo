=====================================

APK：C:\kebbi\app\build\outputs\apk\debug\app-debug.apk

一、這次修正的重點
------------------
1. 修正 Nuwa SDK 初始化順序。
   原本直接呼叫：
   - NuwaRobotManager.getInstance().init(this)
   - NuwaVoiceManager.getInstance().init(this)

   這會失敗，因為 NuwaRobotManager / NuwaVoiceManager 需要 ApiManager 先初始化。

   現在改成：
   - apiManager = ApiManager.getInstance().init(this, getPackageName())
   - robotManager = NuwaRobotManager.getInstance().init(this)
   - voiceManager = NuwaVoiceManager.getInstance().init(this)

2. 加上 SDK ready 檢查。
   Speak、Play Dance Motion、Test Built-in Motions、Stop Motion 都會先檢查 manager 是否為 null，以及 isInit() 是否為 true。
   這樣 SDK 還沒 ready 時不會直接 crash。

3. 新增 Test Built-in Motions 按鈕。
   這個按鈕會從 Kebbi 內建 motion list 取前 5 個 motion，依序播放，用來確認機器人動作 API 是否真的可用。

二、重要變數說明
----------------
POSE_MODEL
- 值：pose_landmarker_lite.task
- 用途：MediaPipe Pose Landmarker 的模型檔名。

FRAME_INTERVAL_MS
- 值：200
- 用途：分析影片時，每 200ms 抽一張 frame 做人體姿勢偵測。

MIN_DANCE_EVENT_GAP_MS
- 值：600
- 用途：避免同一個姿勢事件太密集重複寫入舞步序列。

MOTION_STEP_MS
- 值：1200
- 用途：播放舞步序列或測試 motion 時，每個 motion 之間等待 1.2 秒。

MOTION_TEST_COUNT
- 值：5
- 用途：Test Built-in Motions 一次測試前 5 個內建 motion。

apiManager
- 型別：ApiManager
- 用途：Nuwa SDK 的核心初始化入口。必須先初始化它，robotManager 和 voiceManager 才能使用。

robotManager
- 型別：NuwaRobotManager
- 用途：取得 motion list、播放 motion、停止 motion。

voiceManager
- 型別：NuwaVoiceManager
- 用途：讓 Kebbi 說話、停止 TTS。

latestDanceSteps
- 型別：List<DanceStep>
- 用途：保存最近一次影片分析後產生的舞步事件序列。

dancePlaybackStopped
- 型別：boolean
- 用途：Stop Motion 按下後中止舞步序列或 motion 測試序列。

DanceStep
- 欄位：timeMs、eventType
- 用途：代表影片中某個時間點偵測到的姿勢事件，例如 LEFT_HAND_UP、RIGHT_HAND_UP、BOTH_HANDS_UP、LEAN_LEFT、LEAN_RIGHT。

三、主要函式說明
----------------
onCreate(...)
- 初始化 UI。
- 初始化 ApiManager、NuwaRobotManager、NuwaVoiceManager。
- 初始化 MediaPipe Pose Landmarker。
- 設定按鈕事件。

speak()
- 檢查 voiceManager 是否 ready。
- 呼叫 voiceManager.startTTS("Hello, I am Kebbi.")。

analyzeDanceVideo(Uri videoUri)
- 從影片每 200ms 抽 frame。
- 使用 MediaPipe 偵測人體 33 個 landmark。
- 輸出 dance_pose_landmarks.csv。
- 同時判斷簡單姿勢事件，輸出 dance_motion_plan.csv。
- 將事件保存到 latestDanceSteps。

detectDanceEvent(...)
- 根據肩膀、手腕、髖部 landmark 判斷：
  - LEFT_HAND_UP
  - RIGHT_HAND_UP
  - BOTH_HANDS_UP
  - LEAN_LEFT
  - LEAN_RIGHT

playDanceMotion()
- 如果 latestDanceSteps 有資料，就依序播放對應 motion。
- 如果尚未分析影片，會退回播放第一個內建 motion。

chooseMotionForEvent(...)
- 把事件類型對應到 motion list 中不同 index 的內建 motion。
- 目前是展示版對應，不是精準舞蹈控制。

playFirstAvailableMotion()
- 取得 Kebbi 內建 motion list。
- 播放第一個可用 motion。

testBuiltInMotions()
- 取得 Kebbi 內建 motion list。
- 播放前 5 個 motion。
- 用來確認 Kebbi 動作功能是否真的可用。

stopMotion()
- 設定 dancePlaybackStopped = true。
- 停止 motion。
- 停止 TTS。

五、目前限制
------------
1. Test Built-in Motions 只是測試內建 motion，不代表影片已能精準轉成舞蹈。
2. Play Dance Motion 目前是簡單事件對應 motion list index，還不是細緻的關節角度控制。
3. 若 motion 間隔太短，前一個 motion 可能會被下一個 motion 中斷；目前測試用 1.2 秒間隔，適合快速確認 API 可用。
4. logcat 仍會看到 ConnectionManager$ReceiveDataCallback 的 ClassNotFound 訊息，但實測不影響目前 TTS 和 motion 播放。
