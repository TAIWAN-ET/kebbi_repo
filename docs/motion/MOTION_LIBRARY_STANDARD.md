## 0. 一句話

把 30fps 的連續姿勢流，轉成**少量、可參數化、可重建的動作原子（token）**：

```
右手在 1 秒內轉一圈
  → 30 幀 × 6 馬達 = 180 次逐幀控制
  → 1 個 token：RIGHT_WRIST | CIRCLE | r=0.40 | rev=1.00 | T=1000ms | CW
  → 播放時只展開 9 個關鍵幀
```

這份標準定義「怎麼抽幀、怎麼切段、怎麼辨識、怎麼表示、怎麼驗收」。
程式與文件使用同一組門檻，門檻只有一個來源：`SamplingConfig`。

## 1. 問題定義

### 1.1 為什麼需要動作庫

| 問題 | 現況 | 動作庫的解法 |
|---|---|---|
| 計算量大 | 每幀都要算 33 landmark → 角度 → 6 個馬達指令 | 每段動作只算一次，播放時用參數展開 |
| 指令太密 | 30fps × 6 馬達 = 180 指令/秒 | 1 個 CIRCLE token，展開後約 8 指令/秒 |
| 動作難比較 | 要比 33 個座標 | 比 token（類型、半徑、方向、圈數、週期） |
| 換模型就重寫 | 直接綁 MediaPipe 欄位 | 只依賴「肩寬正規化座標」 |
| 無法解釋 | 黑盒映射 | 每個 token 都有幾何理由與信心值 |

### 1.2 設計原則

1. **抽幀優先**：先決定「看多密」，再談辨識。取樣不足時，寧可標記 `UNDERSAMPLED`，不硬猜。
2. **語意優先**：token 描述「做什麼」（畫圓、揮手、抬起），不是「第幾幀的座標」。
3. **可重建**：每個 token 必須能還原成軌跡，且 RMSE 在門檻內。
4. **不丟資料**：無法辨識時退回 `FREEFORM` 稀疏關鍵幀，不 silently drop。
5. **可擴充**：新增動作 = 新增動作庫條目與（必要時）一個分類規則，播放器不用改。
6. **純數學**：v1 不使用 AI 推論；AI 只適合離線標註與稽核（見 `MOTION_STANDARD_APPENDIX.md` §11）。

## 2. 名詞

| 名詞 | 定義 |
|---|---|
| 取樣（sample） | 從影片抽出的一幀姿勢 |
| 週期（cycle） | 動作重複一次的時間，例如手轉一圈 1000ms |
| 動作原子（primitive / token） | 一段可用少量參數描述的動作 |
| 動作腳本（MotionScript） | 一串 token + 時間 + 統計 |
| 展開（expansion） | 把 token 還原成播放關鍵幀 |
| 保真度（fidelity） | 重建軌跡與原始軌跡的接近程度 |
| SPC | samples per cycle，每個週期的取樣點數 |

座標系固定為：

```
原點 = 左右肩中點
x 向右為正
y 向下為正（畫面座標）
單位 = 肩寬（shoulder width）
```

因此 `(0, 0)` 是肩中心，`r = 0.4` 代表半徑 0.4 個肩寬。
方向定義：**畫面順時針 = CW = 角度增加**（因為 y 向下）。

## 3. 抽幀標準（Sampling Standard）

### 3.1 理論依據：Nyquist + 幾何取樣

- 取樣頻率 `f_s` 必須至少是動作最高頻率的 2 倍：`f_s >= 2 f_max`。
- 人體舞蹈中，有意義的肢體往復頻率約 3Hz（每秒 3 次來回）。
- 因此最低 `f_s = 6Hz`；本標準採 **10Hz（100ms）**，保留 3.3 倍餘裕。
- 但「畫圓」不只是頻率問題，還要看**幾何**：
  - 要判斷方向與曲率，一個圓至少需要 **8 點/圈**（理想）。
  - 最低可接受 **5 點/圈**；低於 5 點不得聲稱辨識出圓。
- 公式：

```
建議間隔 = clamp( 週期 / 8, 33ms, 100ms )
```

| 動作週期 | 建議間隔 | 每圈點數 |
|---|---|---|
| 500ms | 63ms | 7.9 |
| 1000ms | 100ms | 10.0 |
| 2000ms | 100ms | 20.0 |

### 3.2 Aliasing（混疊）標準案例

以「半徑 0.4、1 秒一圈」為例：

| 抽幀率 | 點數 | 結果 | 標準判定 |
|---|---|---|---|
| 1fps | 1 | 看起來像靜止 | 不可辨識 |
| 2fps | 3 | 退化成直線／FREEFORM | **不得判成 CIRCLE** |
| 5fps | 6 | 可辨識，信心較低（~0.81） | 可接受，標記低信心 |
| 10fps | 11 | 高信心（~0.98） | 建議值 |
| 30fps | 31 | 最高精度，但計算量 3 倍 | 只在離線校正使用 |

> 這張表就是「抽幀原理」的核心：**取樣率不足時，複雜動作會 alias 成簡單動作**。
> 所以程式一定要有 `samplesPerCycle` 與 `UNDERSAMPLED` 旗標，不能只看分類結果。

### 3.3 抽幀規則（v1 固定）

| 規則 | 值 | 說明 |
|---|---|---|
| 基準間隔 | 100ms | 10Hz，一般舞蹈 |
| 最密間隔 | 33ms | 快速動作自適應時使用 |
| 最寬間隔 | 333ms | 停滯時降頻 |
| 理想 SPC | 8 | 低於此值信心打折 |
| 最低 SPC | 5 | 低於此值不得判 CIRCLE |
| 停滯門檻 | 300ms | 進入 HOLD |
| 位移死區 | 0.02 肩寬 | 小於此值視為抖動 |
| 活動速度門檻 | 0.12 肩寬/秒 | 低於此值視為沒在動 |
| 合併間隔 | 150ms | 短暫掉速不切段 |
| 最短片段 | 200ms / 3 點 | 更短不產生 token |

### 3.4 前處理規則

1. **時間單調**：時間戳必須嚴格遞增；重複時間（<1ms）丟棄。
2. **遮擋**：`visibility < 0.5` 或 `presence < 0.5` 的點不進入軌跡。
3. **離群值**：手腕離肩中心超過 4 個肩寬視為追蹤錯誤，丟棄。
4. **平滑**：分類統計使用窗口 3 的移動平均；**端點不平滑**，避免圓的起終點被往內拉而少算圈數。
5. **重建用原始點**：token 的幾何參數（圓心、半徑、折線）用未平滑資料拟合，避免圓半徑縮小。
6. **間隔中斷**：若時間 gap > 3 倍中位間隔，視為新片段（目前版本由 `MotionScriptFactory` 以可見性過濾，後續可加 split）。

### 3.5 自適應抽幀（建議的下一階段）

離線分析建議兩遍：

```
Pass 1：5Hz 快速掃描 → 找出「有在動」的窗口
Pass 2：只對活動窗口用 10~30Hz 重抽 → 補到 8 點/圈
```

這樣長影片的總計算量接近 5Hz，但快速手部動作仍有足夠點數。

## 4. 動作原子詞彙（v1）

| token | 意義 | 參數 | 機器人執行碼 | 展開點/圈 |
|---|---|---|---|---|
| `HOLD` | 靜止/停頓 | 位置、時間 | `HOLD` | 1 |
| `CIRCLE` | 2D 畫圓（可多圈） | 圓心、半徑、方向、圈數、週期 | `ARM_CIRCLE` | 8 |
| `SWING` | 直線來回擺盪 | 振幅、週期、方向 | `ARM_SWING` | 8 |
| `WAVE` | 手高於肩的揮手 | 振幅、週期 | `ARM_WAVE` | 8 |
| `RAISE` | 單向抬起 | 起點、終點、時間 | `ARM_RAISE` | 2 |
| `LOWER` | 單向放下 | 起點、終點、時間 | `ARM_LOWER` | 2 |
| `TURN_L` | 頭/軀幹左轉 | 角度、時間 | `HEAD_TURN` | 2 |
| `TURN_R` | 頭/軀幹右轉 | 角度、時間 | `HEAD_TURN` | 2 |
| `NOD` | 點頭 | 次數、週期 | `HEAD_NOD` | 8 |
| `SHAKE` | 搖頭 | 次數、週期 | `HEAD_SHAKE` | 8 |
| `LEAN_L` | 軀幹左傾 | 角度、時間 | `TORSO_LEAN` | 2 |

## 5. 辨識演算法

### 5.1 幾何特徵

對一條軌跡 `p0..pn-1`：

| 特徵 | 公式 | 用途 |
|---|---|---|
| 路徑長 `P` | `Σ |p_i - p_i-1|` | 動作量 |
| 淨位移 `D` | `|p_n-1 - p_0|` | 是否回到原點 |
| 閉合度 `closure` | `D / P` | 圓形接近 0 |
| 有號面積 `A` | `0.5 Σ (x_i y_i+1 - x_i+1 y_i)` | 方向、圓度 |
| 繞行角 `W` | `Σ wrapPi(θ_i - θ_i-1)`，θ 對質心 | 圈數、方向 |
| 圈數 `rev` | `|W| / 2π` | 多圈動作 |
| 圓度 `circ` | `4π|A| · max(1,rev) / P²` | 圓 vs 直線 |
| 方向反轉數 | 主要軸速度變號次數 | 擺盪、揮手、點頭 |
| 線性度 `lin` | `D / P` | 單向抬起 |
| SPC | `n · 週期 / 總時長` | 取樣是否足夠 |
| 週期 `T` | `rev >= 0.5 ? 時長/rev : 2·時長/反轉數` | 播放速度 |

方向：`W > 0` = 畫面順時針（CW）。

### 5.2 分類決策樹（順序固定）

```
1. HOLD
   P < max(deadband, 0.03) 或 bbox 對角 < deadband

2. CIRCLE（僅手臂）
   rev >= 0.65
   且 closure <= 0.45
   且 circ >= 0.45
   且 SPC >= 4.5（最低 5 點的容差）

3. 擺盪（SWING / WAVE / NOD / SHAKE）
   方向反轉 >= 2 且 P > 0.10

4. 單向（RAISE / LOWER / TURN / LEAN）
   lin >= 0.55 且主要位移 > 對應門檻

5. 其他 → FREEFORM（RDP 稀疏關鍵幀）
```

補充：

- `WAVE` vs `SWING`：該段手腕中心 y < -0.05（高於肩）→ WAVE。
- `NOD` vs `SHAKE`：垂直包圍盒較大 → NOD；水平較大 → SHAKE。
- 頭部軌跡的 x 單位是 `headYaw / 45°`；軀幹 x 單位是 `bodyLean`（肩寬倍數）。

### 5.3 信心值

| 類型 | 公式（0~1） |
|---|---|
| CIRCLE | `0.40 + 0.35·min(1,circ) + 0.15·(1-closure) + 0.10·sampleQ`；rev<0.85 再 ×0.85 |
| 擺盪 | `0.35 + 0.25·min(1,反轉/4) + 0.25·(1-circ) + 0.15·sampleQ` |
| 單向 | `0.50 + 0.35·lin + 0.15·sampleQ` |
| HOLD | 1.0 |

`sampleQ = clamp((SPC - 5) / (8 - 5), 0, 1)`。
低於 `minConfidence = 0.60` 一律退回 FREEFORM，不硬猜。

### 5.4 分段（Segmentation）

1. 對每個取樣點計算前後速度與位移。
2. 速度 >= 0.12 肩寬/秒，或單步位移 >= 0.02 肩寬 → 標記為活動。
3. 連續活動點合併；短於 150ms 的掉速不切斷（避免圓的頂點被切成兩段）。
4. 只保留 >= 3 點且 >= 200ms 的片段。
5. 片段之間 >= 300ms → 插入 HOLD。

### 5.5 複合動作切分（MDL）

一個片段可能包含多個動作，例如「畫圓 + 順勢抬手」。
v1 用**重建誤差 + 表示成本**遞迴切分：

```
baseScore  = RMSE(整段, 單一 token) + 0.006 × tokenCost
splitScore = 加權 RMSE(左, 右)     + 0.006 × (cost(左)+cost(右))

若 splitScore < baseScore × 0.80 → 切成兩個，遞迴處理
```

`tokenCost`：CIRCLE = 2（參數）、HOLD = 1、折線型 = 關鍵幀數。

為什麼需要 cost：
如果只用 RMSE，程式會用「很多關鍵幀的 SWING」去硬湊任何曲線，語意反而錯。
加上 cost 後，能用 2 個參數的圓會優先於 9 個關鍵幀的假擺盪。
這就是 **MDL（Minimum Description Length）** 的精神：最短的描述就是最好的描述。

### 5.6 無法辨識時

- 用 Ramer–Douglas–Peucker（RDP）簡化，容差 0.02 肩寬。
- RDP 使用**點到線段**距離，不是點到無限直線；否則折返與停滯段會被誤刪。
- 輸出 `FREEFORM`，保留時間與稀疏點。
- 絕對不允許「因為不認識就丟掉」。
